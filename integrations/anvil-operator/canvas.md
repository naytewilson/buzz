# ANVIL Control Room

This channel is the visible collaboration surface for ANVIL work. ANVIL remains authoritative.

## Use

1. Mention **@ANVIL Operator** and state the desired outcome.
2. The operator performs source-truth preflight and reports the package, ownership, scope, and blockers.
3. Work proceeds only after ANVIL's active contract authorizes mutation.
4. Progress, test evidence, receipts, commits, and PRs are posted in the originating thread.

## Hard boundaries

- No direct Buzz-to-ANVIL Postgres writes.
- No direct Dell-node writes to canonical Postgres.
- No unclaimed ANVIL work.
- No secrets in Buzz messages or receipts.
- A reaction or message is not canonical approval until ANVIL records it.

## Completion evidence

A task is not complete merely because an agent answered, edited files, or ran one test. Completion requires the declared gates, reviewed diff, durable receipt, exact repository state, and any separately authorized integration action.
